# План запуска Show Ring: сервер, конфигурация, что подготовить

Этот документ — «с чего начать». Он отвечает на вопросы *сколько нужно серверов,
какой мощности, от чего можно отказаться и что зарегистрировать заранее* и задаёт
порядок действий. Сами команды — в пошаговой инструкции
[`deployment-linux.md`](deployment-linux.md), здесь на неё ссылки вида «шаг 8».

---

## 1. Короткие ответы

| Вопрос | Ответ |
|---|---|
| Сколько серверов? | **Один VPS.** Весь стек (база, очереди, хранилище файлов, API, воркеры, фронт, nginx, бэкапы) поднимается одной командой `docker compose` на одной машине. |
| Минимальная конфигурация | **2 vCPU, 4 ГБ RAM, 40 ГБ NVMe/SSD, Ubuntu 24.04, публичный IPv4.** |
| А на 2 ГБ RAM? | Запустится, но впритык: сборка фронта (Next.js) на сервере съедает 1,5–2 ГБ и может упасть по нехватке памяти. Только с файлом подкачки 4 ГБ (раздел 6) и `UVICORN_WORKERS=1`. Экономия — пара сотен рублей в месяц, проблем — много. Не рекомендую. |
| Можно ли не ставить хранилище картинок (MinIO)? | **Не стоит.** Без переделки кода приложение без него не работает (раздел 3), а сам MinIO занимает ~100–200 МБ памяти. Правильно — поднять всё сразу. |
| Нужен ли домен? | **Да, для настоящего запуска.** Без HTTPS вход не работает: куки входа в прод-режиме ставятся с флагом `Secure`, а браузер шлёт их только по HTTPS. По голому IP сайт откроется, но залогиниться не получится. |
| Что ещё обязательно? | SMS-шлюз (регистрация по телефону) и почтовый сервис (письма подтверждения). Без них приложение в прод-режиме откажется стартовать (раздел 4). |

> Цифры по памяти ниже — **оценки** по устройству стека и лимитам в
> `docker-compose.prod.yml`, а не замеры. После запуска посмотрите реальное
> потребление командой `docker stats --no-stream` и при необходимости смените тариф:
> у облачных хостингов это делается за пару минут без переустановки.

## 2. Что работает на сервере

Все сервисы — контейнеры Docker из `docker-compose.yml` + `docker-compose.prod.yml`.
Ставить вручную Python, PostgreSQL и т. п. не нужно.

| Контейнер | Что делает | Память (оценка) | Можно выключить? |
|---|---|---|---|
| `nginx` | Единственный вход снаружи (порты 80/443): `/` → фронт, `/api/` → API, лимиты запросов | ~10–20 МБ | Нет |
| `web` | Фронтенд (Next.js) | ~150–300 МБ (лимит 512 МБ) | Нет |
| `api` | Бэкенд FastAPI, `UVICORN_WORKERS` процессов | ~150–250 МБ на процесс (лимит 512 МБ) | Нет; на старте хватит 1–2 процессов |
| `postgres` | База данных | ~100–300 МБ | Нет |
| `redis` | Кэш, лимиты, капча, realtime-уведомления | ~10–30 МБ | Нет |
| `rabbitmq` | Очереди задач между API и воркерами | ~120–200 МБ | Нет (раздел 3) |
| `minio` | Хранилище файлов: фото, аватары, PDF-документы. Образ — `pgsty/minio`, поддерживаемый форк: официальный MinIO заархивирован | ~100–200 МБ | Нет (раздел 3) |
| `worker` | Генерация документов (PDF) | ~100–200 МБ | Нет |
| `worker-files` | Превью и водяные знаки фото | ~100–300 МБ при обработке | Нет |
| `worker-outbox`, `worker-events`, `worker-email` | Доставка событий и отправка писем | ~80–120 МБ каждый | Нет: без них не уходит ни одно письмо |
| `backup` | Ночной дамп базы и копия файлов | ~10 МБ (в простое) | Технически да, но без бэкапов запускаться нельзя |
| `migrate`, `minio-init` | Одноразовые: миграции базы и создание бакета | 0 (завершаются) | — |
| `certbot` | Продление HTTPS-сертификата | ~10 МБ | Включается только когда есть домен (профиль `tls`) |

Итого в работе — примерно **1,5–2,5 ГБ**. Плюс ОС, плюс пик во время сборки
образов при деплое. Отсюда 4 ГБ как разумный минимум.

**Диск.** Образы и кэш сборки Docker — 5–10 ГБ, база и файлы растут со временем,
бэкапы хранят 7 дневных и 4 недельные копии базы **и полную копию файлов** из MinIO
(то есть файлы лежат на диске дважды). 40 ГБ хватит на старт, 60–80 ГБ — с запасом.
Кэш старых сборок периодически чистить: `docker builder prune -f`.

## 3. От чего можно отказаться, а от чего нет

### MinIO (хранилище картинок и файлов) — оставить

Через MinIO работают:
- все загрузки пользователей: фото собак и питомников, фото в объявлениях,
  картинки в блоге, документы собаки;
- сгенерированные PDF (заявки, каталоги, дипломы) — воркер кладёт их туда;
- превью картинок — `worker-files` читает оригинал и пишет варианты;
- бэкап файлов — `backup` зеркалит бакет;
- проверка здоровья — `/api/health` проверяет MinIO.

Кроме того, `api` и воркеры в `docker-compose.yml` ждут готовности `minio`
(`depends_on`) — без него они просто не стартуют. Чтобы отказаться от MinIO, надо
менять код и compose, а экономия — ~150 МБ памяти. Не выгодно.

Если позже захочется вынести файлы с сервера — не выключать хранилище, а переключить
приложение на внешнее S3-совместимое облако (Selectel, Yandex Object Storage, VK
Cloud): код уже работает по протоколу S3, понадобится только правка
`docker-compose.yml` (сейчас адрес `http://minio:9000` там прописан жёстко). Это
задача на потом, не для первого запуска.

### RabbitMQ и воркеры — оставить

Через очереди идут письма, PDF, обработка фото и статистика рекламы. Без
RabbitMQ API запустится, но задачи будут копиться и не выполняться.

### Что реально можно сэкономить на старте

| Что | Как | Выигрыш |
|---|---|---|
| Процессы API | `UVICORN_WORKERS=1` в `.env` (по умолчанию 2) | ~150–250 МБ RAM |
| Внешние бэкапы | Пока не задавать `BACKUP_S3_*` — копии только на этом же сервере | Не платить за облачное хранилище. **Риск:** умрёт сервер — умрут и бэкапы. Подключить в первые недели после запуска. |
| Демо-данные | Не запускать `seed_demo` на боевом сервере | Чистая база |
| Защита от DDoS | Пока не подключать (`deployment-linux.md`, 5.3) | Подключить, когда появятся реальные пользователи |
| Автодеплой | Обновлять вручную `deploy/deploy.sh` (шаг 14) вместо раннера GitHub (шаг 15) | Меньше настройки на старте |

## 4. Что зарегистрировать до деплоя

Прод-шаблон `.env.prod.example` включает `STRICT_CONFIG=true`: приложение
**откажется стартовать**, если SMS-шлюз не настроен, SMTP указывает на локальный
адрес, ключи хранилища дефолтные или выключена капча. Это сделано специально — чтобы
не запустить сайт, где коды входа уходят в лог, а письма никуда. Поэтому до деплоя
нужно завести:

| Сервис | Зачем | Что получить → куда вписать |
|---|---|---|
| **VPS** | Сервер | IP-адрес, логин/пароль или SSH-ключ → для подключения (шаг 1) |
| **Домен** | HTTPS и вход | Домен у любого регистратора (REG.RU, RU-CENTER и др.). В DNS — A-запись на IP сервера (шаг 10) |
| **SMS-шлюз [sms.ru](https://sms.ru)** | Коды подтверждения телефона (регистрация только по телефону) | API-ключ → `SMS_API_KEY` в `.env`. В кабинете sms.ru: **запретить международные направления и задать лимит расходов** — защита от накрутки SMS. Пополнить баланс. |
| **Почтовый сервис (SMTP)** | Подтверждение email, сброс пароля, уведомления | Хост, порт, логин, пароль → `SMTP_*` в `.env`. Подойдёт почта для домена (Яндекс 360, Mail.ru для бизнеса) или сервис рассылок (Unisender Go и т. п.). Сервис выдаст DNS-записи **SPF и DKIM** — их обязательно добавить у регистратора домена, иначе письма уйдут в спам. |
| Telegram-бот (по желанию) | Оповещения о признаках атаки | Токен и id чата → `ALERT_TELEGRAM_*` (`deployment-linux.md`, 5.2) |
| Облачное S3 для бэкапов (по желанию, но скоро) | Копии вне сервера | 4 значения → `BACKUP_S3_*` (шаг 13) |

**Почему хостинг и сервисы российские.** По 152-ФЗ персональные данные граждан РФ
(телефоны, email, ФИО) должны храниться на серверах в России. Выбирайте VPS в
российском дата-центре: Timeweb Cloud, Selectel, REG.RU, Beget, Yandex Cloud и т. п.
По этой же причине не подходит зарубежная защита от DDoS (подробнее — 5.3).

## 5. Как заказать VPS

В панели хостинга при создании сервера выберите:

1. **Регион** — Россия (Москва или Санкт-Петербург).
2. **ОС** — Ubuntu 24.04 LTS (или 22.04). Без панелей управления, без
   предустановленного софта: «чистая» система.
3. **Конфигурация** — 2 vCPU / 4 ГБ RAM / 40+ ГБ NVMe (раздел 1).
4. **Публичный IPv4** — обязательно (для домена и HTTPS).
5. **SSH-ключ** — если панель предлагает добавить ключ, добавьте сразу
   (как его создать — `deployment-linux.md`, 5.1, шаг 2). Иначе хостинг пришлёт
   пароль root.
6. **Автоматические снимки (бэкапы) от хостинга** — если есть за небольшие деньги,
   включите: это вторая страховка помимо нашего `backup`.

Ориентир по цене такой конфигурации у российских хостингов — порядка 1–2 тыс.
рублей в месяц. Цены меняются: сверяйтесь с сайтом хостинга.

## 6. Файл подкачки (swap) — сделать сразу

Подкачка — это место на диске, которое система использует как запасную память.
Если во время сборки фронта памяти не хватит, без подкачки процесс просто убьётся,
и деплой упадёт с непонятной ошибкой. Делается один раз, после шага 2 инструкции:

```bash
sudo fallocate -l 4G /swapfile         # создать файл на 4 ГБ
sudo chmod 600 /swapfile               # доступ только для root
sudo mkswap /swapfile                  # разметить как подкачку
sudo swapon /swapfile                  # включить
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # включать после перезагрузки
free -h                                # проверка: в строке Swap должно быть 4.0Gi
```

Если `swapon` уже показывает подкачку от хостинга (`swapon --show`), отдельный файл
не нужен.

## 7. Порядок действий

Шаги — из [`deployment-linux.md`](deployment-linux.md).

1. **Заказать VPS** (раздел 5) и **домен**. Сразу у регистратора создать A-запись
   домена на IP сервера: DNS обновляется от нескольких минут до суток, пусть идёт,
   пока делаете остальное.
2. **Завести SMS.ru и почту** (раздел 4). Добавить SPF/DKIM-записи почты в DNS.
3. **Подготовить сервер:** шаги 1–5 (SSH, обновления, Git, Docker, файрвол),
   затем **swap** (раздел 6 этого документа), затем 5.1 (защита SSH, fail2ban,
   автообновления, лимит логов).
4. **Скачать код:** шаги 6–7. Оба репозитория рядом в `/opt`.
5. **Заполнить `.env`:** шаг 8 + таблица в разделе 8 ниже.
6. **Запустить:** шаг 9 (первый раз сборка идёт 5–15 минут). Проверить:
   `dc ps` и `curl -fsSL http://localhost/api/health`.
7. **Включить HTTPS:** шаг 10. До этого шага сайт открывается по IP, но вход не
   работает — это нормально.
8. **Админ и справочники:** шаги 11 и 12.1 (справочники обязательны). Демо-данные
   (12.2) на боевом сервере не запускать.
9. **Проверить бэкапы:** шаг 13 — запустить разовый бэкап и убедиться, что в
   `/opt/show-ring-backend/backups` появились файлы.
10. **Пройти чек-лист** (раздел 9).
11. Позже: оповещения (5.2), внешние бэкапы (шаг 13), автодеплой (шаг 15),
    защита от DDoS (5.3).

## 8. Где что прописывать

| Где | Что | Когда |
|---|---|---|
| `/opt/show-ring-backend/.env` (создаётся из `.env.prod.example`) | Все пароли, ключи SMS и почты, настройки | Шаг 8; после правки — `dc up -d` |
| `deploy/nginx/conf.d/show-ring.conf` | Ваш домен вместо `show-ring.example`, включение блока HTTPS | Шаг 10 |
| DNS у регистратора домена | A-запись на IP сервера; SPF и DKIM почтового сервиса | До шага 10 |
| Кабинет sms.ru | Лимит расходов, запрет международных SMS, баланс | До запуска |
| Кабинет хостинга | Снимки диска, смена тарифа, при необходимости — защита от DDoS | По мере надобности |
| GitHub → Settings → Actions → Runners | Раннер для автодеплоя | Шаг 15, по желанию |

### Переменные `.env`, которые нужно заполнить руками

Остальные в шаблоне уже стоят правильно — не трогайте их без причины.

| Переменная | Значение |
|---|---|
| `SECRET_KEY` | `openssl rand -hex 32` |
| `POSTGRES_PASSWORD`, `RABBITMQ_PASSWORD`, `REDIS_PASSWORD` | `openssl rand -hex 24` (каждый свой) |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | `openssl rand -hex 16` / `openssl rand -hex 24` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USE_TLS`, `SMTP_USERNAME`, `SMTP_PASSWORD` | Из кабинета почтового сервиса. Порт 587 → `SMTP_USE_TLS=false`; порт 465 → `SMTP_USE_TLS=true` |
| `SMTP_FROM_EMAIL` | Адрес отправителя на вашем домене, напр. `noreply@ваш-домен.ru` |
| `SMS_API_KEY` | Из кабинета sms.ru |
| `ALLOWED_HOSTS` | `["ваш-домен.ru"]` — после появления домена |
| `FRONTEND_BASE_URL` | `https://ваш-домен.ru` — на него ведут ссылки в письмах |
| `HSTS_ENABLED` | `true` — **только после** того, как HTTPS заработал |
| `NEXT_PUBLIC_SITE_URL` | `https://ваш-домен.ru` — адрес в `sitemap.xml` и `robots.txt` |
| `NEXT_PUBLIC_SITE_INDEXING` | `false`, пока сайт не запущен публично: поисковики и нейросети его не индексируют (`robots.txt` закрыт, на страницах `noindex`). Открыть — `true` |
| `BACKUP_AGE_RECIPIENT` | Публичный ключ `age1…` — бэкапы шифруются. Пару ключей создать на своём компьютере, приватный на сервер не класть (`deployment-linux.md`, 13.1) |
| `UVICORN_WORKERS` | `1` на 4 ГБ, если хотите сэкономить память; `2` по умолчанию |

> Пароли сохраните в менеджере паролей. Без `.env` восстановить сервер из бэкапа
> не получится: в нём ключи к базе и к файлам.

## 9. Чек-лист после запуска

- [ ] `dc ps` — все сервисы `running`/`healthy`, `migrate` и `minio-init` — `exited (0)`.
- [ ] `https://ваш-домен.ru/` открывается, замок в браузере без предупреждений.
- [ ] `https://ваш-домен.ru/api/health` — все компоненты `ok`.
- [ ] Регистрация по телефону: SMS с кодом пришла.
- [ ] Письмо подтверждения email пришло и **не в спам**.
- [ ] Вход под администратором работает, админка открывается.
- [ ] Загрузка фото собаки работает, превью появилось (проверка MinIO и `worker-files`).
- [ ] Разовый бэкап (`dc run --rm backup backup.sh`) создал файлы в `./backups`.
- [ ] `docker stats --no-stream` — сколько памяти занято на самом деле; `free -h` — не уходит ли система в подкачку постоянно (тогда пора на тариф больше).
- [ ] `.env` скопирован в надёжное место вне сервера.

## 10. Известные ограничения

- **`NEXT_PUBLIC_SITE_URL` и `NEXT_PUBLIC_SITE_INDEXING` встраиваются при сборке
  фронта.** После их смены в `.env` нужен `deploy/deploy.sh` (или
  `dc up -d --build web`) — простого перезапуска мало.
- **По голому IP без HTTPS вход не работает** (раздел 1). Для показа без домена —
  туннель Cloudflare/ngrok (последний раздел `deployment-linux.md`).
- Остальной список отложенных задач по деплою и безопасности —
  [`plans/future/technical-debt.md`](plans/future/technical-debt.md), раздел
  «Деплой и сервер».

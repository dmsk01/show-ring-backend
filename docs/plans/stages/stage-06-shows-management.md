# Этап 6: Выставки — управление

### Цель

Реализовать полный цикл управления выставкой: создание, настройка рингов, назначение судей, открытие и закрытие регистрации, запись участников.

### Что появляется в проекте

- Создание выставки (название, ранг, даты, место, стоимость)
- Назначение судей на породы / группы пород
- Конфигурация рингов с расписанием
- Конфигурация допущенных пород (`show_breeds`) — для монопородных / ограниченных выставок
- Онлайн-регистрация собак на выставку
- **Выбор класса владельцем** из списка допустимых по возрасту (не авто-определение)
- Валидация: порода допущена, возраст соответствует выбранному классу, регистрация открыта
- Присвоение каталожных номеров
- Канбан-подобное управление статусами выставки

### Модель данных

Новые таблицы: `shows`, `show_breeds`, `show_judges`, `show_rings`, `show_entries`

Ключевые связи:
- show.organizer_id → users.id (организатор)
- show.rank_id → show_ranks.id
- show_breeds: show ↔ breed (допущенные породы; пусто = все породы)
- show_judges: show ↔ judge ↔ breed/breed_group (many-to-many)
- show_entries: show ↔ dog ↔ show_class (запись, **класс выбран владельцем**)
- show_rings: show ↔ breed ↔ show_class ↔ judge (расписание)

### Бизнес-правила (show_rules.py)

**Определение доступных классов по возрасту:**
```
возраст = дата_выставки - дата_рождения_собаки (в месяцах)

Система вычисляет ВСЕ подходящие классы:
4-6м   → [бэби]
6-9м   → [щенки]
9-15м  → [юниоры]
15-18м → [юниоры, промежуточный, открытый, рабочий, чемпионов]
18-24м → [промежуточный, открытый, рабочий, чемпионов]
24м-96м → [открытый, рабочий, чемпионов]
96м+   → [открытый, рабочий, чемпионов, ветеранов]

Владелец ВЫБИРАЕТ один класс из списка.
Рабочий класс — только при наличии рабочего сертификата.
Класс чемпионов — только при наличии титула Чемпион.
```

> **GET `/shows/{id}/available-classes/{dog_id}`** — возвращает список доступных классов для конкретной собаки.

**Валидация при записи:**
- Собака должна быть зарегистрирована в системе
- Выбранный класс входит в список допустимых по возрасту
- Регистрация на выставку открыта (status = registration_open)
- Собака ещё не записана на эту выставку
- Порода собаки входит в `show_breeds` (если таблица заполнена — монопородная)
- Если `show_breeds` пуста — выставка всепородная, все породы допущены

**Статусная модель выставки:**
```
draft → registration_open → registration_closed → in_progress → completed
                                                                    ↓
                                                               cancelled
```

### Ключевые концепции

- **Many-to-many с доп. полями** — show_judges (судья + порода/группа)
- **Вычисляемый список классов** — система предлагает, владелец выбирает
- **show_breeds** — конфигурация допущенных пород (пусто = все)
- **Статусная машина** — переходы между статусами с валидацией
- **Бизнес-правила в Service** — show_rules.py отделён от CRUD-логики

### SQL-фокус

| Что изучаем | Как |
|-------------|-----|
| Many-to-many через association table | show_judges, show_entries |
| DATE arithmetic | `AGE(show.date_start, dog.birth_date)` для вычисления возраста |
| Complex JOIN (Core) | Каталог: entries + dogs + breeds + classes + owners |
| GROUP BY + COUNT | Статистика: количество записей по породам/классам |
| Transaction | Запись на выставку: проверка + вставка в одной транзакции |
| SELECT FOR UPDATE | Предотвращение двойной записи при конкурентных запросах |

### Как проверить

1. `POST /shows` — создать выставку ранга CAC
2. `POST /shows/{id}/judges` — назначить судью на группу пород
3. `POST /shows/{id}/rings` — настроить ринги с расписанием
4. `PUT /shows/{id}/status` → registration_open
5. `POST /shows/{id}/entries` — записать собаку, система определяет класс автоматически
6. Попытка записать щенка 3 месяца — ошибка валидации
7. `GET /shows/{id}/entries` — каталог с номерами, породами, классами
